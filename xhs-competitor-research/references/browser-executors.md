# 浏览器执行器选择与切换

## 选择顺序

1. 用户明确回复“确认执行”后，优先使用 Codex 自带的 Chrome 控制能力和用户当前登录态。
2. 先验证主执行器能连接浏览器、创建受控标签页并读取普通页面结构，再开始正式采集。
3. 主执行器失败时先分类，不得看到任意报错就自动换工具。
4. 只有符合“可切换条件”，且执行确认单已预先授权，或备用切换规则为“故障发生后再确认”并已获得用户明确同意，才可切换到已安装的 `web-access` Skill。
5. 两种执行器都不可用时停止，保留已完成结果并说明继续条件。

## 可切换条件

以下属于主执行器自身的非策略性技术故障，可以进入备用确认：

- Codex Chrome 插件缺失、停用或无法建立控制连接；
- 当前环境没有可用的内置 Chrome 控制能力；
- 主执行器发生与目标网站内容、登录和访问策略无关的兼容性或运行故障；
- 采集中主执行器连接意外中断，且已有进度可以安全续采。

浏览器未启动、插件尚未授权或客户尚未完成正常登录时，先按主执行器说明请求客户完成必要操作；不要把可由客户正常完成的准备步骤直接当作切换理由。

## 不得切换的情况

出现以下任一情况时停止并如实报告，不得调用 `web-access`、raw CDP、其他浏览器或间接方式实现同一访问：

- 浏览器安全、网络、组织或域名策略拒绝访问，并要求不得尝试替代路径；
- 用户拒绝浏览器、域名、文件或登录授权；
- 登录墙、验证码、异常验证、平台风控或站点明确拒绝自动化访问；
- DNS、代理、TLS 或目标站点网络故障尚未排除；
- 切换会扩大已确认的权限、目标范围或数据范围。

## 启用 web-access

1. 从当前运行环境动态发现名称为 `web-access` 的已安装 Skill；不得假定 `.codex`、`.claude` 或任何用户目录的绝对路径。
2. 完整读取它的 `SKILL.md`，按其前置检查、浏览器选择、风险提示、标签页管理和结束清理要求执行。读取不完整时不得使用。
3. 如果未安装、依赖检查失败或客户未完成它要求的浏览器准备，标记备用执行器不可用；不得自动下载安装或修改客户环境。
4. 启动前向客户展示 `web-access` 要求的自动化风险提示。若客户未在执行确认单中预先授权备用执行器，则此时等待明确同意。
5. 切换后沿用同一关键词、时间范围、互动门槛、详情页预算和字段标准，不因执行器变化扩大采集范围。

## 连续性与记录

- 内部记录 `browser_adapter_used: codex_chrome | web_access`、切换原因、授权来源和切换时间。
- 中途切换时先保存已采 `note_id`、关键词进度和本轮新建标签页，再从未完成位置续采；不得重新采集已完成样本。
- 两种执行器都只操作本轮新建的标签页，结束时只关闭能够确认归属本轮的标签页。
- `web-access` 只用于公开页面采集。任何飞书读取、解析、写入和回读仍只通过 `lark-cli` 执行。
- 对外只说明“主浏览方式”“备用浏览方式”和实际使用结果，不要求客户理解 CDP、代理端口或内部状态码。
- 错误文案包含“enterprise”时，不据此推断客户使用企业电脑、企业账号或企业网络；只描述为“当前 Codex/浏览器访问策略拒绝”，并给出已验证事实和官方授权或支持渠道。
