# 附件输入与证据规则

## 1. 附件门

附件直读模式只使用本次对话中实际可访问的附件或用户明确给出的本地路径。开始时列出：

- 文件名与格式；
- 工作表或数据对象；
- 原始行数与观察单位；
- 实际识别到的字段；
- 用户希望支持的业务决策。

报告开头必须写“以下分析仅根据本次附件：`<文件名>`”。没有附件时输出 `ATTACHMENT_REQUIRED` 并停止，不从历史文件、模型记忆或网络补出 200–300 篇样本。

## 2. 支持格式

`scripts/analyze_attachment.py` 原生支持 CSV、JSON、JSONL；XLSX 需要当前 Python 环境可导入 `openpyxl`。缺少依赖时明确报告，使用当前环境可靠的表格读取能力另存为 UTF-8 CSV，保留原附件且记录原工作表，不静默跳过。

PDF、DOCX 或非逐行表格先提取为“一行一篇笔记”的结构化表，再进入统计。提取过程保留来源页码或段落索引。

## 3. 观察单位与去重

- 默认一行是一篇笔记；若一篇笔记跨多行，先聚合到笔记粒度。
- 去重优先级：`note_id` → 规范 URL → 标题与正文的稳定摘要键。
- 同一笔记的多个关键词来源可以合并，但不能把重复行当成多个样本。
- 原始附件只读保存；清洗后数据另存，不覆盖原件。
- 所有案例保留 `note_id`；没有 `note_id` 时保留附件行号或页码。

## 4. 字段能力矩阵

先按下表判断分析能力，再开始写结论：

| 分析模块 | 最低字段 | 缺失时处理 |
|---|---|---|
| 标题与正文模式 | 标题或正文 | 两者都缺失则该行无效 |
| Tag 频次与共现 | Tag | 标记不可分析 |
| 头/腰/尾分层 | 一套可比较的互动指标，至少 30 条完整记录且有差异 | 不分层，不生成“爆款占比” |
| 数值变量关联 | 互动指标 + 数值特征，成对有效样本至少 30 | 不输出相关系数或“关键变量” |
| 发布时间 | 可解析发布时间 | 不推断最佳时间 |
| 账号类型 | 账号类型 | 不比较账号影响 |
| 视觉元素 | 图片数量、首图/图片类型或可访问图片 | 不从正文猜图片形式 |
| 前 3 秒 | 视频开头、分镜或带时间码转写 | 只有正文时改分析“前 50 字” |
| 评论驱动 | 评论正文或结构化评论字段 | 只能分析正文中的互动引导 |
| 低竞争 Tag | 样本外的平台供给/搜索/竞争基线 | 只能写“本样本中的潜力 Tag” |
| 预期互动量 | 同账号或同类内容历史验证数据 | 改写为触发机制、验证指标和假设 |

只有标题、正文和 Tag 时，可以做内容模式、语义需求、标题公式、关键词/Tag 样本统计和策略假设；不能做互动分层、相关性、视觉、发布时间或账号类型结论。

## 5. 互动口径

1. 优先使用附件已有且口径一致的总互动字段。
2. 没有总互动时，在全体样本中选择覆盖率足够的一组相同组成项，例如点赞 + 收藏 + 评论；一行缺少任一组成项时，该行不进入精确分层。
3. 不同笔记不能使用不同组成项后仍放进同一排名。
4. 不可见值是缺失，不是 `0`；“1.2万”等显示值需保留原值并解析为数值。
5. 原始互动量受账号规模、发布时间和曝光量影响；缺少粉丝数或曝光量时，不写成内容的独立因果效果。

## 6. 分层与关联

- 分层只使用互动口径完整的实际样本，按互动值降序形成头部 10%、腰部 30%、尾部 60%；披露实际人数。
- 为保持比例可复算，边界并列值使用稳定键排序后切分，并单独披露边界并列，提示层级差异可能不稳健。
- 少于 30 条完整互动记录、互动值没有变化或关键缺失严重时，不执行分层。
- 数值变量默认使用 Spearman 等级相关；每个变量披露 `n`、相关系数、缺失率和口径。
- 脚本仅把 `|ρ| ≥ 0.10` 的变量列入 `top_variables`，最多 5 个；低于阈值的已检验变量保留在完整列表中，用于说明样本未支持明显单调关联。
- 类别变量使用分组样本量与中位数/占比对比，不把类别编码后强行计算相关。
- 只写“关联较强的 3–5 个变量”，不能写“贡献最大”或因果关系。

## 7. 语义编码量表

先制定代码本，再逐篇编码；同一轮研究不得中途改变类别含义。

### 情绪强度 1–5

1. 中性描述，无明显情绪词。
2. 轻度偏好或利益提示。
3. 明确好奇、期待、担忧或共鸣。
4. 强冲突、焦虑、紧迫或强烈获得感。
5. 极端、绝对、恐惧或夸张承诺；同时标记内容风险。

### 推荐枚举

- 笔记类型：教程、测评、种草、避坑、情感共鸣、热点、案例故事、清单对比、其他。
- 标题钩子：数字、疑问、反差、结果前置、身份、场景、稀缺、权威、共鸣、其他。
- 开头钩子：疑问、数据、冲突、结果、共鸣、场景、权威、无明显钩子。
- 价值呈现：步骤、清单、对比、案例、故事、问答、过程展示、其他。
- 信任手段：真实经历、数据、前后对比、专业来源、用户反馈、过程透明、无明显信任信号。
- 结尾行动：评论、收藏、分享、关注、产品行动、无明确行动。
- 需求：功能性、情感性、社交性分别编码；没有证据时留空，不强行三类齐全。

语义编码属于【派生】；需求机制和“为什么有效”通常属于【基于样本的推断】。至少抽查每类 3 条或全样本 10%（取较大者），记录修订后的代码本。

## 8. 证据账本

每个关键结论建立一行证据：

| 字段 | 要求 |
|---|---|
| `claim_id` | 稳定编号，如 `F-01`、`I-03` |
| `结论` | 一句话陈述，不把关联写成因果 |
| `证据等级` | 【事实】/【派生】/【基于样本的推断】/【待验证】 |
| `样本范围` | 全体、头部、某类型或某字段完整子样本 |
| `分子/分母` | 百分比必须填写 |
| `统计量与方法` | 均值、中位数、Spearman、频次或共现 |
| `案例索引` | 1–3 个 `note_id` 或来源行号 |
| `限制` | 缺失、偏差、并列、样本外不可推广等 |

无法填入分母或来源索引的数字结论不得进入正文。
