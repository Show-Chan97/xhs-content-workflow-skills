# xhs-competitor-research

小红书批量竞品研究 Skill。它围绕业务决策、关键词、竞品范围和样本标准，分批采集公开笔记，建立可续采的结构化样本，再完成内容分层、爆款因子、用户需求和内容策略分析。

## 适用场景

- 新品立项和赛道研究；
- 品牌或竞品内容复盘；
- 月度、季度内容策略研究；
- 用户需求、痛点和反对意见归纳；
- 研究标题、开头、内容结构和视觉形式与互动表现的关联；
- 建立可复核的公开笔记样本集。

本 Skill 不负责每日简报，也不直接生成日更内容。对应需求请分别使用 `xhs-daily-monitor` 和 `xhs-trend-content`。

## 安装

先克隆完整仓库，再从仓库根目录安装：

```bash
git clone https://github.com/Show-Chan97/xhs-content-workflow-skills.git
cd xhs-content-workflow-skills
./install.sh xhs-competitor-research
```

Windows PowerShell 在仓库根目录运行：

```powershell
.\install.ps1 xhs-competitor-research
```

也可以手动复制完整目录：

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
cp -R xhs-competitor-research "${CODEX_HOME:-$HOME/.codex}/skills/"
```

不要只复制 `SKILL.md`，必须同时保留 `agents/` 和 `references/`。

## 调用示例

```text
使用 $xhs-competitor-research，研究小红书益生菌赛道，目标是为新品内容定位提供依据，最终保留 50 篇有效样本。
```

```text
帮我设计一项小红书竞品研究，比较三个品牌近 90 天高互动内容的标题、开头、视觉形式和用户需求。
```

首次调用不会立即批量浏览。Skill 会先确认研究问题、样本定义和交付要求。

## 客户首次使用

第一次使用时直接输入：

```text
使用 $xhs-competitor-research，这是我第一次使用，请帮我确定研究目标和样本范围。
```

Skill 会用 2–3 轮问题先明确这项研究要支持什么业务决策，再确认品牌、关键词、时间范围、有效样本数量和报告要求，每轮最多 3 个问题。遇到“浏览候选数量”和“最终有效样本数量”时，会先用例子解释区别，不要求客户理解研究术语。

设置完成后会先生成可复制的【客户配置卡】，再生成研究执行确认单。没有收到“确认执行”前，不会批量浏览或写入飞书。

## 执行流程

1. 首次使用时进入客户引导，并输出【已识别】【需要确认】【暂用默认值】。
2. 先明确研究要支持的业务决策，再定义样本。
3. 区分“浏览候选数量”和“最终有效样本数量”。
4. 校验关键词、竞品范围、纳入/排除规则、互动门槛和样本目标。
5. 先生成【客户配置卡】，再生成【研究执行确认单】。
6. 用户明确回复“确认执行”后，才开始批量浏览或写入飞书。
7. 串行低频、分批采集，并在每批结束后保存检查点和抽样复核。
8. 清洗样本，记录缺失、失败、重复和采集偏差。
9. 按实际达标样本分层并完成分析。
10. 交付研究报告、结构化样本和执行限制说明。

## 建议准备的信息

- 客户或项目名称；
- 研究最终要支持的业务决策；
- 主关键词、相关关键词和竞品范围；
- 纳入与排除条件；
- 采集开始和结束日期；
- 互动指标、比较符和整数阈值；
- 部分互动数据的处理方式；
- 候选浏览量或最终有效样本量；
- 每篇需要提取的字段和头部评论数量；
- 内容分类标准；
- 希望验证的假设和分析模块；
- 是否需要原始数据；
- 是否允许分批、中断续采及可接受执行时长；
- 飞书地址和写入方式。

## 推荐默认值

- 去重键：`note_id`；
- 互动定义：页面可见点赞、收藏、评论合计；
- 每篇头部评论：最多 3 条；
- 单批规模：20–30 篇；
- 分层：实际样本的头部 10%、腰部 30%、尾部 60%；
- 每批保存进度并抽样复核。

这些参数只会作为【暂用默认值】展示，仍需用户确认。

## 分批与检查点

每个批次至少保存：

- 已完成关键词和当前关键词；
- 下一批起点；
- 已浏览候选数量；
- 达标 `note_id` 列表和有效样本数；
- 重复、跳过和失败数量；
- 结构化数据集位置；
- 失败日志位置；
- 浏览器执行器和保存时间。

遇到验证码、登录墙、平台风控、连续页面失效、连接中断或达到时间上限时停止，并从最后成功检查点继续。续采前必须读取已有 `note_id`，避免重复。

## 数据字段与质量

默认样本字段包括：

- `note_id` 和规范链接；
- 来源关键词；
- 标题、正文或描述、话题标签；
- 发布时间和作者；
- 内容类型；
- 点赞、收藏、评论的原始值和标准化值；
- 部分可见状态和达标状态；
- 头部评论；
- 批次、缺失字段和备注。

原始数据与清洗后数据分开保存。不可见互动项使用 `null`，展示时写“不可见”，不得写成 `0`。同一 `note_id` 合并来源关键词并保留字段最完整的版本。

## 分析模块

- 头部、腰部、尾部内容特征；
- 爆款内容因子；
- 标题、开头、内容结构和视觉形式；
- 用户需求分层；
- 点击、停留和互动驱动线索；
- 痛点、爽点、痒点；
- 评论区问题和反对意见；
- 典型案例和反例；
- 可复用内容生产框架。

所有关键结论应标记为【事实】【基于样本的推断】或【待验证】。变量关联只能描述关联，不能写成因果。

## 结论强度

- 少于 30 篇：只做主题归纳、典型案例和初步假设；
- 30–99 篇：可以做探索性分层和趋势判断，并显著标注限制；
- 100–300 篇：可以做较完整的分层和变量关联分析，仍需说明样本偏差；
- 关键字段严重缺失时，应降低结论强度，不因样本量大而忽略数据质量。

目标超过 100 篇时，必须先确认批次、进度保存、时间成本和风控限制；目标 200–300 篇时，不承诺一次运行必然完成。

## 报告结构

1. 研究目标与决策问题；
2. 采集方法、时间范围和互动口径；
3. 目标样本与实际样本；
4. 数据缺失、样本偏差和执行限制；
5. 样本整体分布；
6. 头部/腰部/尾部特征；
7. 爆款因子与关键变量关联；
8. 用户需求分层；
9. 点击、停留和互动驱动；
10. 痛点、爽点、痒点；
11. 典型案例和反例；
12. 可复用内容生产框架；
13. 策略建议；
14. 待验证假设。

用户需要原始数据时，另附结构化样本表、字段说明和数据质量摘要。

## 内容与平台边界

- 只读取公开页面和用户当前登录态下正常可见的内容；
- 串行低频访问，不并发扫页；
- 不采集与研究无关的个人敏感信息；
- 不点赞、不收藏、不关注、不评论、不私信、不自动发布；
- 不绕过登录墙、验证码、异常验证或平台风控；
- 不读取密码、Cookie、令牌或浏览器敏感配置；
- 不估算隐藏互动数字，不降低门槛凑数；
- 修改关键词、时间范围或样本门槛前必须重新确认。
