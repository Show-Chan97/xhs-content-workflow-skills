# 小红书批量竞品研究

## 输入路由

1. 先识别本次对话实际可访问的附件、文件路径、工作表和用户目标，不把历史文件、示例数据或未提供的材料当作本次输入。
2. 已提供逐篇笔记附件时，进入“附件直读模式”；完整读取 [references/attachment-input-and-evidence.md](references/attachment-input-and-evidence.md) 和 [references/attachment-analysis-and-output.md](references/attachment-analysis-and-output.md)，不启动浏览器。
3. 用户要求“根据附件”分析但本次没有可访问附件时，停止并输出 `ATTACHMENT_REQUIRED`，请用户上传或给出明确路径；不得凭模型记忆继续分析。
4. 用户要求从小红书采集样本，或明确表示没有现成数据时，进入“采集研究模式”。
5. 输入意图确实无法判断时，只询问一个路由问题：分析现有附件，还是先采集公开样本。

## 附件直读模式

1. 列出实际附件文件名、格式、工作表、原始行数和观察单位，并声明“以下分析仅根据本次附件”。
2. 先运行 `scripts/analyze_attachment.py` 完成字段映射、去重、缺失率、互动口径、10%/30%/60% 分层、数值特征关联和 Tag 统计；不得用语言模型心算替代可复算统计。
3. 先交付字段能力矩阵。字段不足的模块必须写“无法判断”和所缺字段，不能用行业常识补齐。
4. 按固定量表分批完成内容类型、标题结构、情绪强度、用户需求、开头钩子、价值呈现、信任手段和结尾行动的语义编码；保存逐篇编码与 `note_id` 或来源行号，再汇总比例。
5. 按 [references/attachment-analysis-and-output.md](references/attachment-analysis-and-output.md) 输出证据表、完整分析和可选研究验证稿。策略草案与样本事实分开呈现。
6. 本地只读检查、统计和用户已要求的本地报告输出不需要“确认执行”；浏览补数、飞书写入或其他外部动作仍需按对应规则另行确认。

从当前 Skill 目录动态解析脚本路径，并显式指定派生输出目录：

```bash
python3 <skill-dir>/scripts/analyze_attachment.py <attachment> --output-dir <derived-output-dir>
```

XLSX 有多个工作表时增加 `--sheet <sheet-name>`。脚本输出 `analysis-summary.json`、`cleaned-notes.csv` 和 `semantic-coding-template.csv`；原附件保持只读。

## 采集研究模式

1. 首次使用或信息不完整时，先读取 [references/client-onboarding.md](references/client-onboarding.md)，用客户能理解的业务语言确认决策问题，再定义样本。
2. 输出【已识别】【需要确认】【暂用默认值】，每轮最多询问 3 个关键问题；完成后先生成【客户配置卡】，再读取 [references/intake-and-sample-definition.md](references/intake-and-sample-definition.md) 生成【研究执行确认单】。
3. 未收到明确的“确认执行”前，不批量浏览、不创建定时任务、不写入飞书。
4. 确认后先完整读取 [references/browser-executors.md](references/browser-executors.md)，选择并验证浏览器执行器，再按 [references/batch-and-checkpoint.md](references/batch-and-checkpoint.md) 串行低频、分批采集并保存检查点。
5. 按 [references/dataset-schema.md](references/dataset-schema.md) 保存结构化样本、失败记录和数据质量信息。
6. 全部批次结束或中断后，按 [references/analysis-and-report.md](references/analysis-and-report.md) 清洗、分析和交付；涉及飞书时先完整读取 [references/feishu-cli-policy.md](references/feishu-cli-policy.md)，只通过 `lark-cli` 执行。

## 研究原则

- 观察单位默认是一篇公开小红书笔记。
- “浏览 N 篇候选”和“最终保留 N 篇有效样本”是不同目标；用户未说明时必须确认。
- 所有分层基于实际达标样本，不基于目标数量。
- 样本标准变更会改变研究口径；降低门槛、扩词或扩大时间范围前必须重新确认。
- 区分【事实】【派生】【基于样本的推断】【待验证】；变量关联不得写成因果或“贡献”。
- 报告结论必须同时披露样本量、缺失比例、关键词来源、采集偏差和平台限制。
- 百分比必须能回溯到分子、分母和样本范围；案例必须来自本次附件或本次采集样本。
- “最佳发布时间”“低竞争 Tag”“预期互动量”等平台级或预测性结论，只有对应外部基线或历史验证数据时才能成立。

## 采集模式的平台与浏览器边界

- 只读取公开页面和用户现有登录态下可见内容。
- 串行低频访问，不并发扫页，不采集与研究无关的个人敏感信息。
- 不点赞、不收藏、不关注、不评论、不私信、不自动发布。
- 不索取密码、Cookie、令牌或浏览器配置，不绕过验证码、登录墙或风控。
- 只关闭本次创建的标签页。
- 默认使用 Codex 自带的 Chrome 控制能力；`web-access` 仅作为主执行器发生非策略性技术故障时的候选备用执行器。
- 主执行器失败时先保存检查点、保留原始错误并按 `browser-executors.md` 分类。只有符合可切换条件，且确认单已预先授权或用户另行明确同意，才可切换备用执行器。
- 使用 `web-access` 前从当前运行环境动态发现并完整读取其 `SKILL.md`，执行它要求的前置检查和风险提示；不得写死任何机器的绝对路径。
- 明确的浏览器安全、网络、组织、域名或平台策略拒绝，以及登录墙、验证码和风控，不得通过 `web-access` 或其他通道重试同一访问。
- 无论使用哪个浏览执行器，都继续串行低频执行，不采用并行扫页；飞书操作不得改用浏览器、连接器或直接 API。

## 规模判断

- 目标超过 100 篇：先说明这是长任务，确认批次、进度保存、时长和风控限制。
- 目标 200–300 篇：不得承诺一次运行必然完成。
- 需要长期稳定的大规模数据：优先建议评估授权数据源或合规数据服务。

## 客户交付规则

- 默认把使用者视为首次做结构化竞品研究的业务客户，先解释业务选择，不直接抛出字段表或技术参数。
- 客户只调用本 Skill、说“开始研究”或说“按推荐设置”且未提供附件时，必须进入采集模式首次引导。
- 必须用示例解释候选浏览量与最终有效样本量的区别，不能只让客户在两个术语之间选择。
- 面向客户显示“设置中、等待确认、分批采集中、报告整理中、需要客户操作、已完成”等自然语言，不单独抛出内部状态码或检查点路径。
- 新任务无法保证自动继承旧设置；完成后输出可复制的【客户配置卡】，不声称已经永久保存。

## 完成标准

附件直读模式必须交付附件清单、实际有效样本量、重复与缺失、可执行/不可执行模块、互动口径、证据索引、报告与派生文件位置。采集研究模式必须交付实际达标样本量、失败与跳过数、执行批次、数据缺失、限制、报告位置和飞书状态。中断时保留检查点，并说明最后成功批次与继续条件。
