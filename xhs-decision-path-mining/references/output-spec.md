# 内容元素中台交付规范

## 目录

1. 分析范围与数据质量
2. 核心结论
3. 七段路径总览
4. 七个内容元素库
5. 跨阶段组合方式
6. 生成、审核与培训规则
7. 待验证清单

## 1. 分析范围与数据质量

至少列出：

- 品类、目标、来源文件和时间范围；
- 原始样本数、有效样本数、标题缺失数、重复数、排除数及原因；标题缺失但正文非空的样本计入有效样本；
- 可用字段和缺失字段；
- 是否具备可比的互动或转化数据；
- 样本偏差、截断或代表性限制。

## 2. 核心结论

用 5–10 条说明：

- 哪些阶段元素最丰富或最薄弱；
- 哪些模式跨批次重复出现；
- 哪些只是高频，哪些有互动关联，哪些有真实转化数据支持；
- 当前最值得进入生成、审核或测试环节的元素。

每条结论标注【事实】【推断】或【待验证】。

## 3. 七段路径总览

| 阶段 | 有效元素数 | 头部元素 | 最高覆盖率 | 证据状态 | 主要缺口 |
|---|---:|---|---:|---|---|

没有证据的阶段写“证据不足”，不要留空。

## 4. 七个内容元素库

按 Attention、Relevance、Empathy、Value、Trust、Reasoning、Action 依次输出。每个阶段使用同一字段：

| 字段 | 含义 |
|---|---|
| `element_id` | 稳定 ID，如 `ATT-001` |
| `canonical_element` | 合并同义表达后的元素名称 |
| `reusable_structure` | 含变量位的复用结构，不是原句改写 |
| `psychological_question` | 它试图处理的心理问题，标为推断 |
| `subtype` | 阶段内分类，如恐惧、身份点名、时间信任 |
| `support_count` | 支持它的唯一笔记数 |
| `coverage` | `support_count / valid_count` |
| `author_count` | 作者字段可用时，支持它的唯一作者数 |
| `representative_sources` | 代表 `note_id` 或 `source_anchor` |
| `evidence_excerpt` | 最短必要证据片段 |
| `conclusion_level` | 事实、推断或待验证 |
| `confidence` | 高、中或低，并说明原因 |
| `fact_status` | 样本原话、已获产品证据、待核验或禁用 |
| `usage_guardrail` | 事实、品类、平台或表达限制 |

高优先级元素优先展示 3 个不同来源；只有一个来源时如实展示。

## 5. 跨阶段组合方式

只输出样本实际支持的常见组合。每个组合包含：

- `pattern_id`；
- 阶段顺序；
- 每段承担的任务；
- 代表笔记；
- 适用场景；
- 不适用或冲突条件。

七段完整链可以作为审核框架，但不能假设每篇内容都必须机械包含七段。

## 6. 应用规则

### 内容组合

- 先选择一个目标人群和一个核心任务，再选阶段元素。
- 同一阶段默认只选一个主元素，避免刺激、身份和价值承诺相互打架。
- 所有产品参数、体验、功效、价格和资质必须回到已确认事实。

### AI 批量生成

- 把 `reusable_structure`、允许变量、禁用表达和事实资料一起提供。
- 要求不同草稿更换元素组合，不只替换名词。
- 缺少真实体验时标记 `DRAFT_ONLY` 和待补项。

### 内容审核

逐条检查：阶段任务是否清楚、身份是否具体、场景是否可观察、价值链是否完整、信任依据是否真实、反认知是否有逻辑、行动提示是否与内容匹配。

### 团队培训

用元素 ID 讲解判断依据，展示“有效样本片段—抽象结构—错误用法”三联示例。不得把推断讲成固定人群真相。

## 7. 待验证清单

| hypothesis_id | 候选元素或组合 | 当前依据 | 缺少的数据 | 建议验证方式 | 判断指标 |
|---|---|---|---|---|---|

优先验证高覆盖但缺少行为证据的元素。A/B 测试或历史对照需保持人群、投放、发布时间和内容质量等关键条件尽可能可比；否则只报告观察差异。

## 可选机器可读交付

用户需要 CSV 或 JSON 时，至少保留元素表字段和独立证据映射表：

`element_id, source_anchor, stage, location, evidence_excerpt`

不要只交付合并后的模板而丢失来源映射。
