## 1. 先确认数据粒度

诊断前明确以下四项：

- 时间窗口：单日、近 3 天、近 7 天或自定义区间。
- 每行粒度：必须整理成“一条笔记 × 一个诊断窗口”的快照。
- 归因口径：总支付、7 日支付、自然成交是否来自同一口径。
- 百分比单位：`5%`、数值 `5` 或小数 `0.05` 分别代表什么。

同一笔记有多日明细时先聚合非重叠的日指标。7 日访客、加购、支付金额和 7 日 ROI 若是滚动归因快照，取窗口末日最新值或按数据源说明处理，禁止跨日求和造成重复归因。

## 2. 品牌与产品资料

至少收集：

- 品牌、品类、核心产品线及每条产品定位。
- 人群痛点 → 产品机制、成分或功能 → 应呈现的具体场景。
- 卖点清单及每条卖点的事实证据。
- 价格带、行业参考价及高客单或长决策周期特征。
- 关键竞品，仅用于检查内容是否造成错误心智或价格对比。

资料不足时允许继续做数据诊断，但把人群、卖点和内容建议标成【待验证】。不得补造产品功效、检测、体验或竞品事实。

## 3. 规范字段

### 最小必需字段

| 规范字段 | 常见来源字段 | 用途 |
|---|---|---|
| `note_id` 或 `note_title` | 笔记 ID、笔记标题 | 标识笔记 |
| `impressions` | 展现量、曝光量 | 点击率分母与投放能力 |
| `clicks` 或 `ctr_pct` | 点击量、笔记点击率 | 判断展现到点击 |
| `spend` | 消费、投放消费 | 判断样本与效率 |
| `roi_7d` 或 `revenue_7d` | 7 日支付 ROI、总支付金额 | 判断转化 |

缺少这些字段时不得强行分类投流四象限。

### 推荐投流字段

| 规范字段 | 常见来源字段 | 诊断用途 |
|---|---|---|
| `action_clicks` / `action_ctr_pct` | 行动按钮点击量/率 | 点击到商品意向 |
| `product_visitors` | 7 日商品访客总量 | 商品页到达 |
| `add_to_cart` | 7 日总商品加购量 | 商品页到加购 |
| `orders` / `payers` | 订单数、支付人数 | 成交证据 |
| `cumulative_spend` | 累计消费 | 止损红线；不能由单日消费代替 |
| `consecutive_zero_order_days` | 连续无成交天数 | 止损红线 |
| `performance_stable_days` | 稳定表现天数 | 判断是否具备放量历史证据 |
| `likes` / `saves` / `comments` / `shares` / `follows` | 点赞、收藏、评论、分享、关注 | 内容价值与传播信号 |

### 笔记元信息

| 规范字段 | 常见来源字段 | 诊断用途 |
|---|---|---|
| `ai_type` | A/I 类型 | A 类泛人群种草、I 类精准转化 |
| `owner_type` | 达人/素人/KOS | 比较信任与成本结构 |
| `distribution_status` | 已投、未投、停投、有问题 | 解释当前状态 |
| `product` | 商品链接、关联产品 | 检查人群与价格匹配 |
| `audience_selling_point` | 目标人群+卖点 | 最关键的人工标注 |
| `content_template` | 参考笔记、内容模板 | 识别可复制框架 |
| `surface` | 发现页、搜索页 | 选择合适点击基准 |
| `manual_label` | 人工标注 | 校准人工判断与数据 |
| `roi_decay_observed` | 是否已观察到 ROI 衰减 | 必须是明确的真/假值；缺失不等于“未衰减” |
| `content_product_match_verified` | 内容与商品匹配是否已核查 | 只有明确为真时，脚本才会把“换人群”列为首要动作 |

### 自然流与商品笔记字段

| 规范字段 | 常见来源字段 | 诊断用途 |
|---|---|---|
| `reads` | 阅读量 | 自然流曝光代理 |
| `product_clicks` / `product_ctr_pct` | 商品点击次数/率 | 内容到商品匹配 |
| `store_visits` | 引流店铺主页次数 | 品牌兴趣与单品兴趣差异 |
| `refunds` / `refund_rate_pct` | 退款金额/率 | 检查承诺与履约落差 |

自然流没有消费和 ROI 时，不计算投流四象限；单独报告代理指标。

## 4. 可确定的计算

- 笔记点击率（百分点）=`clicks / impressions × 100`。
- 行动按钮点击率（按源文档口径）=`action_clicks / impressions × 100`。若业务系统使用其他分母，改用业务口径并披露。
- 7 日 ROI=`revenue_7d / spend`，仅在两者属于同一归因窗口时计算；使用倍数口径，`1` 表示回本，不用 `100%` 表示。
- 商品页加购率、加购到支付率等指标，只有在分子分母定义得到确认时才计算。

若 CTR 类源值与复算值相差超过 `0.2` 个百分点、ROI 相差超过 `0.05`，或任一差异跨过本 Skill 使用的决策阈值，保留两者并输出数据冲突，不擅自选择一个继续下结论。更小且不跨阈值的差异视为展示精度误差。

## 5. 数据质量门

- 同一诊断窗口出现重复 `note_id`：先去重或聚合，禁止重复计入总消费。
- 比率缺少分母、ROI 时间窗混用、支付金额与订单信号冲突：标记【待验证】。
- 目标人群+卖点为空：该笔记诊断第一行必须提示缺少人群定位。
- 当天总消费 `<100` 元或有效投流笔记 `<5` 条：报告开头加入低样本警告，但仍诊断高消费单条。
- 数据不足时写明需要补多少天、多少条或哪些字段，不使用笼统的“继续观察”。

## 6. 脚本输入

`scripts/diagnose_notes.py` 接受 UTF-8 CSV 或 JSON 数组。支持上表中的中英文字段别名。默认把不带 `%` 的百分比数值视为百分点；如果输入以 `0.05` 表示 `5%`，传 `--percent-scale ratio`。

示例：

```bash
python3 scripts/diagnose_notes.py notes.csv --pretty
python3 scripts/diagnose_notes.py notes.json --ctr-threshold 5 --roi-threshold 1 --pretty
```
