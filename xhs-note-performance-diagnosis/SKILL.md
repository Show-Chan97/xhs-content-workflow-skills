# 小红书笔记表现诊断

## 标准流程

1. 明确诊断时间窗、数据口径和目标。先读取 [references/input-schema.md](references/input-schema.md)，收集品牌产品资料并把不同来源字段映射到规范字段。
2. 判定数据粒度。优先使用“一条笔记 × 一个诊断窗口”的最新快照；不得把重叠的 7 日归因指标跨日期直接相加。
3. 运行 `scripts/diagnose_notes.py` 校验字段、复算可确定的比率、分类象限并生成动作候选。脚本只接受规范化 CSV 或 JSON，不访问网络、不修改投放账户。
4. 读取 [references/diagnostic-rules.md](references/diagnostic-rules.md)，披露本次点击率、ROI、止损线等阈值，再诊断漏斗、人群和内容。
5. 有封面、标题、正文、评论或商品页素材时直接核查；没有素材时只能把内容原因写成【推断】或【待验证】，不得写成事实。
6. 读取 [references/action-policy.md](references/action-policy.md)，按优先级为每条笔记选择一个首要行动。不得同时给出互相冲突的动作。
7. 读取 [references/output-spec.md](references/output-spec.md)，先输出逐条诊断，再输出全局黄金组合、待验证信号、应停止方向和团队协作问题。

## 数据入口

- 用户给出 CSV、JSON、Excel、飞书表格或多维表格时，先只读获取数据并完成字段映射；涉及飞书时先完整读取 [references/feishu-cli-policy.md](references/feishu-cli-policy.md)，所有读取、链接解析和可选回写只通过 `lark-cli` 执行。除非用户明确要求并回复“确认执行”，不回写原数据源。
- 用户只粘贴少量数据时，可直接分析，但仍要确认百分比单位、ROI 窗口和每行粒度。
- 数据尚未提供时，只索取完成诊断所需的最小字段，不主动浏览、抓取或登录平台。

## 证据标记

- 【事实】：输入中直接存在的数值、文本或素材。
- 【派生】：写明公式后由事实计算出的指标、象限和规则命中。
- 【推断】：由数据模式推测的内容、人群、投放或商品页原因。
- 【待验证】：缺少关键字段、素材或足够样本时需要补查的事项。

每个判断都要同时引用笔记级数字、比较阈值和时间窗口。禁用“表现不错”“数据一般”“再观察”等无条件表达。

## 固定边界

- 把通用阈值视为运营启发式，不包装成行业事实；用户覆盖阈值后必须在报告中披露。
- 不从点击率反推具体封面类型，不把相关性写成因果，不使用“唯一指标”“100% 是正文问题”等绝对表述。
- 未证明“累计消费达到止损线且连续至少 3 天无成交”时，不触发强制停投红线。
- 自然流笔记使用自然流代理指标并单独标记，不与投流四象限混算。
- 本 Skill 只给分析和建议，不自动调整预算、关停计划、修改笔记、控评或写入业务系统。

## 完成标准

只有在数据质量警告、所用阈值、逐条五步诊断、每条唯一首要行动和四类全局洞察均已输出时，才标记完成。证据不足时保留空结论或待验证项，不为填满模板而编造判断。
