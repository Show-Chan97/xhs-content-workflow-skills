# xhs-daily-monitor

小红书每日监控与飞书日报 Skill。它持续追踪指定主题，按时间窗口和可见互动门槛采集公开笔记，使用 `note_id` 去重、分类和总结，再把当日日报追加到用户确认的现有飞书文档。

## 适用场景

- 每日追踪行业、品牌或产品主题；
- 收集热门或潜力笔记；
- 生成选题日报、行业情报或案例库更新；
- 追踪舆情和公开用户反馈；
- 把去重结果定时追加到飞书文档。

本 Skill 不负责批量生成品牌内容，也不适合大样本竞品策略研究。对应需求请分别使用 `xhs-trend-content` 和 `xhs-competitor-research`。

## 安装

先克隆完整仓库，再从仓库根目录安装：

```bash
git clone https://github.com/Show-Chan97/xhs-content-workflow-skills.git
cd xhs-content-workflow-skills
./install.sh xhs-daily-monitor
```

Windows PowerShell 在仓库根目录运行：

```powershell
.\install.ps1 xhs-daily-monitor
```

也可以手动复制完整目录：

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
cp -R xhs-daily-monitor "${CODEX_HOME:-$HOME/.codex}/skills/"
```

不要只复制 `SKILL.md`，必须同时保留 `agents/` 和 `references/`。

## 调用示例

```text
使用 $xhs-daily-monitor，每天上午 9 点监控“小红书护肤趋势”，把达标笔记追加到我的飞书日报。
```

```text
帮我配置一个小红书每日监控：最近 24 小时、可见互动合计大于等于 100、每天最多 10 篇。
```

首次调用不会立即浏览或写入。Skill 会先整理参数并生成执行确认单。

## 客户首次使用

第一次使用时直接输入：

```text
使用 $xhs-daily-monitor，这是我第一次使用，请帮我设置每日监控和飞书日报。
```

Skill 会用 2–3 轮问题确认监控主题、关键词、达标标准、每日数量、执行时间和飞书链接，每轮最多 3 个问题。客户不需要理解浏览器连接方式、去重字段或接口参数，也可以回复“除了飞书链接，其余按推荐设置”。

设置完成后会先生成可复制的【客户配置卡】，再生成执行确认单。没有收到“确认执行”前，不会浏览、建立定时任务或写入飞书。

## 执行流程

1. 首次使用时进入客户引导，并输出【已识别】【需要确认】【暂用默认值】。
2. 分 2–3 轮收集设置，每轮最多询问 3 个会阻塞执行的问题。
3. 校验关键词、时间窗口、互动口径、数量、飞书地址和定时参数。
4. 先生成【客户配置卡】，再生成【小红书每日监控执行确认单】。
5. 用户明确回复“确认执行”后，才开始浏览、创建定时任务或写入飞书。
6. 记录原有标签页，优先用 Codex 自带的 Chrome 插件控制本地 Chrome CDP；每篇纳入样本都打开详情页核验，并使用 `note_id` 去重。
7. 完成全部采集后统一生成日报。
8. 检查当天标题和已有 `note_id`，整段追加一次。
9. 写入后回读目标位置，核对新增标题或文末内容。
10. 汇报实际样本量、回补数量、重复和失败数量及飞书状态。

## 建议准备的信息

- 客户或项目名称；
- 监控主题和核心关键词；
- 组合词、排除关键词、账号或内容类型；
- 首选时间范围和允许的回补范围；
- 互动指标、比较符和整数阈值；
- 目标数量与每日上限；
- 是否沿用、修改或增加分类标签模板，以及洞察重点；
- 现有飞书 `docx` / `wiki` 文档链接；没有链接时 Skill 会提醒补充；
- 同一天重复运行的处理方式；
- 跨日去重范围；
- 立即或定时执行，以及频率、时间和时区。

系统建议的参数只会放入【暂用默认值】，不会被当成用户已经确认的信息。

## 推荐默认值

- 首选时间范围：最近 24 小时；
- 样本不足时回补至最近 7 天；
- 每次最多打开 30 个详情页；只有用户明确授权时才继续向更早结果补足；
- 目标数量：10 篇；
- 每日上限：10 篇；
- 跨日去重：滚动 7 天；
- 零结果仍生成日报；
- 时区：`Asia/Shanghai`。

所有默认值仍需通过执行确认单确认。

## 时间、互动和去重口径

- 按 `primary`、`fallback_7d`、`fallback_older` 标记样本来源；
- 回补前必须完成首选时间窗口内的全部关键词搜索和去重；
- 支持按点赞、可见赞藏评合计、任一单项或组合条件判断；
- “50+”推荐明确为“点赞数达到 50，或赞藏评可见合计达到 50”；
- 同时保留互动数的页面原始值和标准化整数；
- 不可见项写“不可见”，不能写成 `0`；
- 可见小计已达到门槛时才能直接纳入部分可见样本；
- 同一 `note_id` 只保留一条，并合并来源关键词；
- 无法取得 `note_id` 时使用规范 URL 临时去重并明确标记。
- 搜索卡片只用于发现候选，不能代替详情页底部互动核验。

## 飞书写入规则

- 只向用户确认的现有文档追加，不自动新建文档；
- 禁止覆盖历史内容；
- 写入前读取目标文档，检查日期标题和已有 `note_id`；
- 文档名称不能替代链接；未提供链接时停在确认阶段并提醒补充；
- 一次运行只整段追加一次，不逐篇或逐行写入；
- 动态文本和 URL 写入 XML 前必须转义 `&`、`<`、`>`；日报链接优先使用无临时查询参数的规范 URL；
- 支持跳过、只追加新笔记或追加带时间的补充章节；
- 写入后检查返回状态、更新块数量和警告，并再次读取目标位置；
- 无法复核时只能报告“已提交写入但未完成复核”。

## 日报结构

1. 沿用目标文档风格的日期标题；没有既有样式时使用 `YYYY-MM-DD 样本结果`；
2. 关键词、时间窗口、回补和互动口径；
3. 笔记结果表；
4. 今日洞察；
5. 数据限制与排除说明；
6. 浏览器、运行时间、去重和失败数量。

结果表通常包含序号、发布时间/时间层、标题与链接、作者、赞/藏/评、摘要、类型/备注和 `note_id`。内容类型仅为模板参考，执行前会询问用户是否沿用、修改或增加。执行失败与零篇达标分开处理，CDP 不可用时不生成空结果表或今日洞察。

## 内容与平台边界

- 只读取公开页面和用户当前登录态下正常可见的内容；
- 串行低频访问，不并发扫页；
- 不点赞、不收藏、不关注、不评论、不私信、不自动发布；
- 不绕过登录墙、验证码、异常验证或平台风控；
- 不读取密码、Cookie、令牌或浏览器敏感配置；
- 不估算隐藏互动数字，不降低门槛凑数；
- 只关闭本次新建的标签页；
- 飞书无权限时保留待写日报，不声称已经同步。

## 客户看到的运行状态

- 设置中：正在逐步确认监控要求；
- 等待飞书链接：可以继续完善设置，但还不能写入日报；
- 等待确认：配置卡和执行确认单已经生成；
- 执行中：正在采集、核验或整理日报；
- 需要客户操作：需要客户自行登录、授权或处理页面验证；
- 已完成：采集、追加和回读复核全部完成。

## 验证状态

- `SKILL.md` 已通过 `quick_validate.py` 结构校验；
- 安装脚本已在临时 `CODEX_HOME` 中完成整体试装；
- 浏览器采集、定时任务和飞书写入仍应在客户实际环境中分别验证权限与登录状态。
