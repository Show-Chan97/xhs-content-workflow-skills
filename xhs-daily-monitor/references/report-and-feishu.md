# 日报与飞书追加

## 日报结构

1. 日期标题。默认沿用目标文档现有样式；没有可复用样式时使用 `YYYY-MM-DD 样本结果`。
2. 采集口径：执行时间与时区、关键词、搜索排序实际状态、时间窗口、回补情况、互动门槛、详情页预算、实际数量。
3. 结果表格。
4. 今日洞察。
5. 数据限制与排除说明。
6. 运行信息：适配器、运行时间、去重、排除和失败数量。

结果列为：序号、发布时间/时间层、标题与链接、作者、赞/藏/评、摘要、类型/备注、`note_id`。链接使用规范 URL，临时查询参数不写入日报。

洞察只基于当日已核验样本，区分多篇共性与个案，并披露样本量和口径限制。类型字段只使用用户确认的 `selected_labels`，更具体的场景放备注。

## 正常、零结果与失败日报

- 有达标样本：写完整口径、结果表格、今日洞察和限制说明。
- 完成了搜索与详情页核验但零篇达标：仅在 `write_zero_result: true` 时写零结果日报，说明已搜索范围、排除数量和原因。
- CDP 不可用、登录墙或网络中断导致未完成采集：这是执行失败，不是零结果。仅在 `write_failed_run: true` 且本次确认已覆盖时追加简短失败状态；不得生成空表或“今日洞察”。
- 少于目标数量：按实际数量写入，并分开披露“达标样本不足”与“页面无法验证”两类原因，不用旧的低互动内容凑数。

建议 XML 骨架：

```xml
<h1>YYYY-MM-DD 样本结果</h1>
<callout emoji="📌">
  <p><b>采集口径：</b>执行时间；关键词；真实排序状态；24 小时、7 天及更早回补；点赞或可见总互动大于等于阈值；实际样本数。</p>
  <p><b>字段说明：</b>互动按详情页底部可见数字记录为“赞 / 收藏 / 评论”。</p>
</callout>
<table>
  <thead><tr><th>#</th><th>发布时间/时间层</th><th>标题与链接</th><th>作者</th><th>互动</th><th>摘要</th><th>类型/备注</th><th>note_id</th></tr></thead>
  <tbody><!-- 每篇一行；动态文本和 URL 先做 XML 转义 --></tbody>
</table>
<h1>今日洞察</h1>
<ul><li>仅写已核验样本支持的共性或个案。</li></ul>
<h1>数据限制</h1>
<p>披露样本不足、回补、部分可见、重复、排除与页面失败。</p>
```

## 写入步骤

1. 使用飞书文档能力，并完整读取其使用说明。
2. 用户没有提供飞书文档链接时提醒补充，并停止在确认阶段；不得以文档标题代替链接或自行确定写入目标。执行写入前读取目标文档，验证 URL、权限、既有日期标题与表格风格、当天标题及已有 `note_id`。复用格式，不复用旧数据或旧洞察。
3. 仅允许 `append`，禁止 `overwrite`。一次运行整段追加一次，不逐篇写。
4. 当天标题不存在时追加完整日报。
5. 当天标题已存在时执行配置：
   - `skip`：不写。
   - `append_new_only`：剔除已有 `note_id`，只追加“补充 HH:mm”；无新笔记则不写。
   - `append_timed_supplement`：追加带时间的补充章节，仍先去重。
6. 动态内容中的 `&`、`<`、`>` 及 URL 查询参数必须 XML 转义；追加块以目标文档既有日期标题层级开始，不写 `<title>`。
7. 检查返回的 `result`、`updated_blocks_count` 和 `warnings`。只有 `success` 或经核实的 `partial_success` 可报告写入结果。
8. 写入后再次读取新增标题或文末片段。无法验证时明确写“已提交写入但未完成复核”。

CLI 语义示例：

```text
lark-cli docs +update --api-version v2 --as user \
  --doc "客户确认的文档 URL" \
  --command append \
  --content "生成并正确转义的 XML"
```
