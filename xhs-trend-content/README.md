# xhs-trend-content

小红书趋势采集与内容创作 Skill。它围绕指定品类和关键词采集近期高互动公开笔记，提炼趋势、评论反馈和表达结构，再根据用户确认的品牌、产品与事实资料生成多角度内容草稿。

## 适用场景

- 品牌日更选题；
- 小红书代运营内容策划；
- 新品或单品的近期趋势采集；
- 基于公开趋势的种草内容草稿；
- 标题、封面字、置顶评论和图文/视频分镜生成。

本 Skill 不负责长期每日监控，也不适合大样本竞品统计研究。对应需求请分别使用 `xhs-daily-monitor` 和 `xhs-competitor-research`。

## 安装

先克隆完整仓库，再从仓库根目录安装。

macOS：

```bash
./install.sh xhs-trend-content
```

Windows PowerShell：

```powershell
.\install.ps1 xhs-trend-content
```

不要只复制 `SKILL.md`；必须复制完整目录。

目录应保持如下结构：

```text
xhs-trend-content/
├── SKILL.md
├── README.md
├── agents/
│   └── openai.yaml
└── references/
    ├── client-onboarding.md
    ├── intake-and-validation.md
    ├── browser-executors.md
    ├── collection-fields.md
    ├── content-output-spec.md
    ├── compliance.md
    └── feishu-cli-policy.md
```

## 调用示例

显式调用：

```text
使用 $xhs-trend-content，围绕敏感肌修护采集最近 7 天的热门内容趋势，并根据我提供的产品资料生成 3 篇小红书草稿。
```

也可以直接描述需求：

```text
我们是一个新消费护肤品牌，想了解最近小红书上哪些选题互动高，并策划 3 篇笔记。
```

## 客户首次使用

客户不需要提前理解采集参数。第一次使用时可以直接输入：

```text
使用 $xhs-trend-content，这是我第一次使用，请一步一步帮我完成设置。
```

Skill 会用 2–3 轮问题确认品牌产品、目标人群、关键词、事实材料和交付要求，每轮最多 3 个问题。客户可以说“按推荐设置”，系统会预填最近 7 天、最多 10 篇参考样本、生成 3 篇草稿等推荐项。

完成后会先生成【客户配置卡】和【执行确认单】。客户可以保存配置卡供下次复制使用；没有收到“确认执行”前，不会打开小红书、创建定时任务或写入飞书。

如选择飞书交付，链接解析、读取、写入和回读全部通过 `lark-cli` 执行；不使用浏览器、连接器或直接 API 作为备用方式。CLI、授权或权限不满足时会停止飞书步骤并说明需要客户处理的条件。

## 浏览器备用方案

小红书采集优先使用 Codex 自带的 Chrome 控制能力。可选安装 `web-access`，作为主执行器发生非策略性技术故障时的备用 Skill：

```bash
npx skills add eze-is/web-access
```

`web-access` 不随本 Skill 自动安装；它当前要求 Node.js 22+，并需按自身 `SKILL.md` 完成 Chrome 或 Edge 的浏览器准备。运行时会按名称动态发现并完整读取它，不依赖 Windows 或 macOS 的固定目录。

切换必须符合执行确认单中的备用规则；切换后仍使用同一关键词、时间范围、门槛和样本上限，并记录实际执行器。登录墙、验证码、风控或任何明确禁止替代路径的策略拒绝都不会触发备用切换。

## 执行流程

1. 从用户原话中预填信息，输出【已识别】【需要确认】【暂用默认值】。
2. 首次使用时分 2–3 轮引导，每轮最多询问 3 个影响执行的问题。
3. 信息齐全后先生成【客户配置卡】，再生成【执行确认单】。
4. 用户明确回复“确认执行”后，才开始浏览、建立定时任务或写入飞书。
5. 验证 Codex Chrome 主执行器；发生符合条件的技术故障时，按已确认规则切换 `web-access`，再串行低频采集公开笔记。
6. 提炼趋势词、标题结构、开头方式和评论反馈。
7. 根据已确认事实完成产品信息转译并生成不同角度的内容草稿。
8. 按固定日报骨架交付完整报告，而不是只给三篇草稿。
9. 汇报实际样本量、交付数量、数据限制和仍需补充的字段。

## 建议准备的信息

- 客户或项目名称；
- 品类、趋势关键词和排除词；
- 品牌及产品全名；
- 目标人群；
- 产品卖点及对应依据；
- 可公开的真实使用资料；
- 是否允许竞品对比；
- 内容数量、字数、角度和标签；
- 禁用表达、行业合规要求和输出位置；
- 立即执行或定时执行。

没有填写的非阻塞参数会作为【暂用默认值】展示，不会被当成用户已经确认的信息。

## 默认交付规格

用户未另行指定时，Skill 会建议：

- 采集最近 7 天的公开笔记；
- 可见点赞、收藏、评论合计大于等于 300；
- 最多保留 10 篇趋势样本；
- 生成 3 篇、每篇 250–450 字；
- 每篇附 5 个标题、3 条封面压字、3 条置顶评论和 5–6 个分镜。
- 每篇附 5–8 个与品类、人群、场景和品牌事实对应的话题标签。

这些参数仍需通过执行确认单确认。

## 内容与平台边界

- 只读取公开页面和用户当前登录态下正常可见的内容；
- 不点赞、不收藏、不关注、不评论、不私信、不自动发布；
- 不绕过登录墙、验证码、异常验证或平台风控；
- 不通过备用执行器绕过任何明确的浏览器安全、网络、组织、域名或平台策略拒绝；
- 不读取密码、Cookie、令牌或浏览器敏感配置；
- 不推算页面未展示的互动数字；
- 不虚构用户身份、使用周期、效果变化、检测报告或专家背书；
- 不使用医疗化、绝对化、效果保证或无法证明的领先性表达。

缺少真实体验时，可以生成“待补资料草稿”（内部标记为 `DRAFT_ONLY`），但必须列出【需用户补充/替换】。

## 输出结构

完整交付默认按迪安旧版日报骨架输出：

1. 本次执行状态或自动任务状态；
2. 今日抓取样本；
3. 本轮爆款词与句式，并附评论问题和推广 / 活动信号；
4. 产品信息转译；
5. 每日三篇笔记视角，用户指定其他数量时相应调整；
6. 下次自动任务输出格式，未创建任务时明确说明；
7. 发布前需要补充的信息。

每篇草稿包含状态、目标人群、内容角度、待补字段、5 个标题、3 条封面压字、250–450 字正文、5–8 个话题标签、3 条置顶评论、5–6 个分镜，以及事实依据和样本推断。

## 验证状态

- `quick_validate.py` 结构校验通过；
- 信息不完整场景测试通过：会先补充信息，不会直接执行；
- 无依据功效和专家背书场景测试通过：会拦截风险表达；
- 无真实使用资料时会采用 `DRAFT_ONLY`，不会虚构第一人称体验。
- 主执行器、`web-access` 备用条件、动态发现和禁止切换边界已通过静态契约校验；真实浏览器切换仍需在客户环境中验证。

正式运行前，建议检查执行确认单是否完整保留【已识别】【需要确认】【暂用默认值】三个模块。
