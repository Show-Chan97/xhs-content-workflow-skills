# xhs-trend-content

小红书趋势采集与内容创作 Skill。它围绕指定品类和关键词采集近期高互动公开笔记，提炼趋势、评论反馈和表达结构，再根据用户确认的品牌、产品与事实资料生成多角度内容草稿。

## 适用场景

- 品牌日更选题；
- 小红书代运营内容策划；
- 新品或单品的近期趋势采集；
- 基于公开趋势的种草内容草稿；
- 标题、封面字、置顶评论和图文/视频分镜生成。

本 Skill 不负责长期每日监控，也不适合大样本竞品统计研究。对应需求请分别使用 `xhs-daily-monitor` 和 `xhs-competitor-research`。

## 安装

复制完整的 `xhs-trend-content` 目录到 Codex Skills 目录，不要只复制 `SKILL.md`：

```bash
cp -R xhs-trend-content "${CODEX_HOME:-$HOME/.codex}/skills/"
```

目录应保持如下结构：

```text
xhs-trend-content/
├── SKILL.md
├── README.md
├── agents/
│   └── openai.yaml
└── references/
    ├── intake-and-validation.md
    ├── collection-fields.md
    ├── content-output-spec.md
    └── compliance.md
```

## 调用示例

显式调用：

```text
使用 $xhs-trend-content，围绕敏感肌修护采集最近 7 天的热门内容趋势，并根据我提供的产品资料生成 3 篇小红书草稿。
```

也可以直接描述需求：

```text
我们是一个新消费护肤品牌，想了解最近小红书上哪些选题互动高，并策划 3 篇笔记。
```

## 执行流程

1. 从用户原话中预填信息，输出【已识别】【需要确认】【暂用默认值】。
2. 每轮最多询问 5 个影响执行的问题。
3. 信息齐全后生成【执行确认单】。
4. 用户明确回复“确认执行”后，才开始浏览、建立定时任务或写入飞书。
5. 串行低频采集公开笔记，按 `note_id` 去重并标记部分可见数据。
6. 提炼趋势词、标题结构、开头方式和评论反馈。
7. 根据已确认事实生成不同角度的内容草稿。
8. 汇报实际样本量、交付数量、数据限制和仍需补充的字段。

## 建议准备的信息

- 客户或项目名称；
- 品类、趋势关键词和排除词；
- 品牌及产品全名；
- 目标人群；
- 产品卖点及对应依据；
- 可公开的真实使用资料；
- 是否允许竞品对比；
- 内容数量、字数、角度和标签；
- 禁用表达、行业合规要求和输出位置；
- 立即执行或定时执行。

没有填写的非阻塞参数会作为【暂用默认值】展示，不会被当成用户已经确认的信息。

## 默认交付规格

用户未另行指定时，Skill 会建议：

- 采集最近 7 天的公开笔记；
- 可见点赞、收藏、评论合计大于等于 300；
- 最多保留 10 篇趋势样本；
- 生成 3 篇、每篇 250–450 字；
- 每篇附 5 个标题、3 条封面压字、3 条置顶评论和 5–6 个分镜。

这些参数仍需通过执行确认单确认。

## 内容与平台边界

- 只读取公开页面和用户当前登录态下正常可见的内容；
- 不点赞、不收藏、不关注、不评论、不私信、不自动发布；
- 不绕过登录墙、验证码、异常验证或平台风控；
- 不读取密码、Cookie、令牌或浏览器敏感配置；
- 不推算页面未展示的互动数字；
- 不虚构用户身份、使用周期、效果变化、检测报告或专家背书；
- 不使用医疗化、绝对化、效果保证或无法证明的领先性表达。

缺少真实体验时，可以生成标记为 `DRAFT_ONLY` 的草稿，但必须列出【需用户补充/替换】。

## 输出结构

每篇内容通常包含：

- 状态：`READY` 或 `DRAFT_ONLY`；
- 内容角度；
- 标题候选；
- 封面压字；
- 正文；
- 置顶评论；
- 图片或视频分镜；
- 使用到的趋势词或句式；
- 【事实依据】；
- 【基于样本的推断】；
- 【需用户补充/替换】。

## 验证状态

- `quick_validate.py` 结构校验通过；
- 信息不完整场景测试通过：会先补充信息，不会直接执行；
- 无依据功效和专家背书场景测试通过：会拦截风险表达；
- 无真实使用资料时会采用 `DRAFT_ONLY`，不会虚构第一人称体验。

正式运行前，建议检查执行确认单是否完整保留【已识别】【需要确认】【暂用默认值】三个模块。
