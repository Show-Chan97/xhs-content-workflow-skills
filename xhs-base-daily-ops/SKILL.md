# 小红书 Base 日数据运营

## 必需入口

- 要求用户提供一个飞书多维表格 URL，或能够唯一解析的 Base 标题。没有数据源时输出 `SOURCE_REQUIRED`，只索取该信息，不假定任何表或数据存在。
- 将“找到并确认三张原始表”作为所有模式的第一阶段。不得把 Base 中顺序靠前的三张表直接当成目标表。
- 开始前动态定位并完整读取当前环境的 `lark-base` 与 `lark-shared` Skill；遵守其中的 URL 解析、身份、分页、查询和权限规则，不写死本机路径。
- 开始飞书操作前完整读取 [references/feishu-cli-policy.md](references/feishu-cli-policy.md)。Base 的 URL 解析、读取、查询、修改和回读全部通过 `lark-cli` 执行。
- 找不到 `lark-base`、`lark-shared` 或 `lark-cli` 时，输出缺少的依赖并停止；不得改用浏览器、连接器、通用飞书能力或直接 API。
- 默认使用用户身份和用户已经授权的权限。不得索取密码、Cookie、访问令牌或应用密钥。

## 运行模式

1. `inspect`：只读识别三张表，核验字段、粒度、唯一键、日期范围与关联覆盖。
2. `review`：在 `inspect` 通过后，生成指定日期及近 7/14 天复盘；未指定模式时默认使用此模式。
3. `plan`：提出关联、汇总表、仪表盘、workflow 或同步验收方案，不修改 Base。
4. `apply`：仅在用户审核拟变更清单并明确回复“确认执行”后修改 Base，完成后回读验证。

## 标准流程

1. 读取 [references/base-discovery.md](references/base-discovery.md)，解析 Base、列全数据表并读取真实字段。
2. 依据“表名只是线索，字段签名与记录粒度才是证据”的规则，分别识别：
   - 投流数据底表；
   - 商品笔记数据底表；
   - 笔记元信息表。
3. 输出三表识别结果。任一角色为 `ambiguous` 或 `missing` 时停止后续联查，请用户消歧或补表；不得猜测。
4. 读取 [references/schema-and-quality.md](references/schema-and-quality.md)，校验稳定 `笔记ID`、字段类型、唯一键、数据日期、重复、空值与关联覆盖。
5. 根据模式继续：
   - `inspect`：按 [references/output-contract.md](references/output-contract.md) 交付诊断结果后结束；
   - `review`：读取 [references/metric-and-review.md](references/metric-and-review.md)，让 Base 云端完成筛选、分组、聚合与 TopN，再生成复盘；
   - `plan` / `apply`：读取 [references/implementation-options.md](references/implementation-options.md)，先审查现有关系、视图、仪表盘和 workflow，再设计最小变更。
6. 所有模式都按 [references/output-contract.md](references/output-contract.md) 汇报真实表、真实字段、查询范围、公式、限制与状态。

## 强制停机条件

- 只有“笔记标题”或含义不明的“笔记标题/笔记ID”字段：不得把标题当稳定连接键。
- 两个以上候选表都满足同一角色：列出候选及差异，请用户选择。
- 投流表声明为“笔记 × 日期 × 计划”粒度但没有计划字段：标记粒度缺口，不声称已验证唯一性。
- 商品笔记表没有快照日期：可读取当前累计快照，但不得输出日新增阅读或自然流量日趋势。
- 表 2 或表 3 的笔记 ID 重复且没有可解释粒度：停止多表汇总，避免重复放大金额或阅读量。
- 缺少消费或支付金额：不输出 ROI；缺少展现或点击：不输出 CTR。
- 只读到默认分页、有限样本或 `has_more=true`：不得形成“全部、最高、异常、Top”等全局结论。

## 读写边界

- URL 解析、Base/表/字段/结构读取，以及用户明确要求的只读查询可直接执行。
- 创建、重命名、删除或更新表、字段、记录、关联、公式、lookup、视图、仪表盘、workflow、自动化和权限前，必须展示：目标 Base、对象、操作、影响范围、回退方式和验证方式，并等待“确认执行”。
- 一次确认只覆盖清单中的变更。新增对象、扩大日期范围、覆盖历史数据或改变关联键时重新确认。
- 写入后读取真实结构或计算结果复核；无法回读时写“已提交但未完成复核”，不得标记 `COMPLETE`。

## 证据边界

- 区分【事实】【计算结果】【基于数据的推断】【待验证】。
- 阅读量是自然与投流总阅读时，不据此声称投流带来自然增长。
- 投流支付金额与商品笔记支付金额可能属于不同归因口径，不直接相加。
- 分组表现是关联，不写成内容模板、人群或达人导致了结果。
- “加预算、停投、改封面、换人群”只能作为待验证动作建议；没有用户确认的阈值时不自动下结论，更不执行投放操作。
- 本 Skill 读取已有 Base 并验收数据或设计方案；文档未定义真实上游 API、增量水位、重试和回补链路，不声称已完成数据同步。
