# 关联、看板与同步方案

## 先审查现状

在提出或执行任何写入前，读取真实的表、字段、link/lookup、视图、仪表盘、组件和 workflow。不要重复创建已有对象，也不要使用猜测的名称或 ID。

## 三种实施路径

### 路径 C：现有结构上的只读复盘或仪表盘

适合当天获得结果。若所需维度与指标已经在同一可查询表，或已有可靠 link/lookup，可直接设计：

- 指标卡：消费、投流归因支付、ROI、展现、投流笔记数、有成交笔记数、CTR；
- 趋势：日消费、日支付、日 ROI；
- 分布与交叉：A/I、人群、模板、归属和笔记 CTR。

“不改表结构”不代表天然支持跨表图表。若 A/I 或模板只在元信息表、ROI 只在投流表且没有可用关联，必须先选择路径 A，或只交付外部只读分析。

### 路径 A：补齐稳定关联

适合长期在 Base 内按笔记联查。先确认规范笔记 ID、重复键和目标关联方向，再设计 link/lookup 或汇总字段。

创建或修改 link/lookup 会改变 Base，必须先输出变更对象、字段定义、回填范围、重复与空值处理、回退方法和验证查询，并等待“确认执行”。

### 路径 B：日维度汇总表

适合事实表持续增长、常用查询变慢或需要稳定日报接口时。文档中的“笔记超过 500 条”只能作为经验提示，不是硬阈值；还要结合事实行数、计划数量、查询延迟和看板性能。

汇总表至少保留日期、消费、展现、点击、投流归因支付、投流笔记数和可用的商品笔记指标。比率由分子分母重算。

写入必须使用明确的幂等键，例如 `日期 × 产品 × 必要分组维度`，采用 upsert 或等价去重策略；不能每天无条件追加重复行。

## Dashboard 写入要求

- 完整读取当前 `lark-base` Skill 的 Dashboard 指引和组件配置规则。
- 新建前先列出现有仪表盘与组件，避免重复。
- 组件的数据源表名和字段名必须来自真实返回。
- 组件必须串行创建；每个创建结果成功后再继续下一个。
- 只有用户明确要求时才智能重排已有仪表盘。
- 完成后读取仪表盘结构和关键组件计算结果，验证名称、类型、数据源、筛选与指标。

## Workflow 与外部同步

文档只给出飞书 workflow、n8n、Make 或定时脚本等方向，没有定义真实上游接口。设计同步方案时至少补齐：

- 上游系统与授权方式；
- 拉取频率、时区、数据延迟和最大业务日期；
- 增量水位与回补窗口；
- 幂等键、upsert 规则和迟到数据处理；
- 失败重试、错误记录、对账与告警；
- 金额、百分比、退款和支付归因口径。

不得索取或保存用户密码、Cookie 或令牌。没有真实上游能力时只交付方案，不声称完成同步。

## 变更确认单

```text
【目标 Base】名称与可识别链接
【拟变更对象】表 / 字段 / 关联 / 视图 / 仪表盘 / workflow
【具体操作】逐项列出 create / update / delete / backfill
【影响范围】涉及表、字段、历史记录和日期范围
【数据保护】幂等键、备份或回退方式
【验证方式】写后结构、记录数、唯一性、关联覆盖、图表结果
【确认口令】确认执行
```
