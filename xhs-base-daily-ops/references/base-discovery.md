# Base 数据源发现与三表识别

## 目标

从用户指定的同一个飞书多维表格中，找到三个互不相同的数据表，并用真实字段与粒度证明每张表的角色。

## 读取顺序

1. 用户给 URL 时，用当前 `lark-base` Skill 规定的 `base +url-resolve` 解析真实 `base_token`；只给标题时使用标题解析，多候选必须请用户消歧。
2. 读取 Base 本体，确认名称、访问身份和权限状态。
3. 使用 `base +table-list` 列出全部数据表。处理分页，不能只看默认第一页。
4. 对所有可能候选执行 `base +field-list`。表较多时可先按名称缩小范围，但若任一角色没有唯一候选，必须扩大到全部表。
5. 记录真实表名、`table_id`、字段名、字段 ID、字段类型和分页状态。
6. 必要时读取少量记录判断值形态；样本只能验证合理性，不能证明全表唯一或完整。
7. 用 Base 云端查询能力验证重复键、空值、日期范围和关联覆盖，不用默认页或本地少量数据代替全量校验。

## 三表角色签名

名称只用于召回，不能单独作为确认依据。允许用户的表名与下列示例不同。

| 角色 | 名称线索 | 硬条件 | 粒度证据 |
|---|---|---|---|
| 投流数据底表 | 投流、广告、聚光、计划、投放明细 | 稳定笔记 ID、投放日期，以及展现、点击、消费、支付中的至少三类投流字段 | 原始明细应能用 `笔记ID × 日期 × 计划ID/计划名称` 定位；无计划字段时只能确认是笔记日汇总表 |
| 商品笔记数据底表 | 商品笔记、原生数据、笔记表现、商品转化 | 稳定笔记 ID，以及阅读、商品点击、进店、订单、支付、退款中的至少两类原生或商品指标 | 当前快照通常一条笔记一行；历史快照必须有快照日期并以 `笔记ID × 快照日期` 定位 |
| 笔记元信息表 | 元信息、运营管理、内容资产、笔记标签 | 稳定笔记 ID，以及 A/I、归属、投放状态、产品、人群卖点、模板、切口、人工标注中的至少两类分类字段 | `笔记ID` 应唯一；多产品或多标签必须有明确的数据建模方式 |

## 识别规则

- 确认 `笔记ID` 是独立、稳定的文本键。标题、行号、Base `record_id` 和会变化的 URL 展示文本都不能替代业务键。
- 同一张表不得同时填充两个角色，除非用户明确说明其数据已经合表；这时标记为非标准模型并重新校验粒度。
- 先匹配字段语义，再检查字段类型与少量值形态，最后用云端查询验证粒度。
- 两张候选表得分接近时不自行选择。展示各自满足项、缺失项和粒度证据。
- 不因表名完全一致就跳过字段校验，也不因表名不同就拒绝字段签名完整的候选表。

## 固定识别状态

- `confirmed`：唯一候选满足硬条件，关键字段类型与粒度已经验证。
- `candidate`：字段签名基本吻合，但粒度、日期或值形态仍未完全验证。
- `ambiguous`：两个以上候选都可能满足；必须请用户选择或补充业务定义。
- `missing`：没有候选；列出缺少的表角色和最小字段要求，不自动创建。

只有三张表全部为 `confirmed`，或用户明确接受某项已披露的 `candidate` 限制后，才能进入跨表复盘。
