# 输出契约

完成数据源解析后，每次输出保留以下模块。无可用数据时写“暂无”并说明原因，不静默省略。状态为 `DEPENDENCY_REQUIRED` 或 `SOURCE_REQUIRED` 时，只需输出状态、缺少项和明确下一步。

## 1. 数据源与执行范围

- Base 名称与用户可识别链接；
- 模式：`inspect` / `review` / `plan` / `apply`；
- 报告日期、时区、趋势窗口和筛选条件；
- 当前状态。

## 2. 三表识别结果

| 角色 | 实际表 | 状态 | 关键字段证据 | 粒度 | 缺失/歧义 |
|---|---|---|---|---|---|
| 投流数据底表 |  |  |  |  |  |
| 商品笔记数据底表 |  |  |  |  |  |
| 笔记元信息表 |  |  |  |  |  |

## 3. 字段、粒度与关联校验

- 唯一键与重复数；
- 关键字段空值与类型；
- 数据日期范围和最大日期；
- 投流笔记到表 2、表 3 的匹配数、缺失数和覆盖率；
- 金额、百分比、退款、归因窗口与快照口径。

## 4. 指定日期核心指标

展示指标值，并为每个派生指标写明公式与分母。能力不足时写 `N/A` 和缺少的字段。

## 5. 近 7/14 天趋势

展示真实日期范围、聚合方式、突变候选与同步新鲜度；不能用有限样本替代全量趋势。

## 6. 笔记与分群表现

列出使用的维度、样本量、分子分母、覆盖率和结果。需要逐条笔记时展示用户可读标题与稳定笔记 ID。

## 7. Top5 与异常候选

写明排序指标、方向、阈值、观察窗口和候选原因。无业务阈值时只给观察，不给自动加预算或停投结论。

## 8. 数据质量与限制

列出缺表、缺字段、重复、空值、分页、口径、同步延迟、关联未命中和无法验证的部分。

同时给出一个明确的【下一步】：需要用户选择哪张候选表、补哪个字段、确认哪个口径、提供哪段查询结果，或回复哪条确认口令。不得只说“数据不足”。

## 9. 结论分级

- 【事实】：Base 实际结构、真实记录或云端查询结果。
- 【计算结果】：注明公式、范围、筛选、聚合与时区。
- 【基于数据的推断】：解释推断依据，不写成因果。
- 【待验证】：阈值、字段语义、归因、同步延迟或行动建议。

## 10. 变更与确认状态

涉及 `plan` 或 `apply` 时列出拟变更/已变更对象、影响范围、回退与验证结果。

固定状态：

- `DEPENDENCY_REQUIRED`：缺少 `lark-cli`、`lark-base` 或必要认证能力。
- `SOURCE_REQUIRED`：尚无可解析 Base。
- `TABLE_MAPPING_REQUIRED`：三表缺失或识别有歧义。
- `SCHEMA_REPAIR_REQUIRED`：三表已定位，但关键键、粒度或字段不足。
- `READ_ONLY_READY`：可完成只读复盘或方案设计。
- `WRITE_CONFIRMATION_REQUIRED`：已给出精确变更清单，等待“确认执行”。
- `PARTIAL`：只完成部分查询或写入，明确剩余条件。
- `COMPLETE`：目标已完成且必要回读验证通过。
