# 三表字段、粒度与数据质量契约

## 投流数据底表

预期业务粒度：`笔记 × 日期 × 计划`。若上游已经聚合到笔记日，必须明确写成 `笔记 × 日期`，不能假装仍有计划明细。

| 字段组 | 典型字段 | 用途 |
|---|---|---|
| 主键维度 | 投放日期、笔记 ID、计划 ID/名称 | 唯一性、日期筛选、去重 |
| 业务维度 | 笔记标题、产品/商品 | 展示与分组；标题不是连接键 |
| 流量 | 展现量、点击量 | 计算 CTR |
| 成本与成交 | 消费、投流归因支付金额 | 计算 ROI |
| 中间转化 | 商品访客、加购 | 漏斗诊断 |
| 互动 | 点赞、收藏、评论、分享、关注 | 内容反馈，缺失时不补零 |

若文档或表名宣称“按计划”但没有计划字段，将其记录为模型缺口。若同一笔记日确实只有一行，可作为聚合表使用，但不能回答计划级问题。

## 商品笔记数据底表

预期业务粒度有两种，必须先判定：

- 当前累计快照：`笔记ID` 唯一，只能回答当前累计值。
- 历史快照：`笔记ID × 快照日期` 唯一，可在口径一致时计算日变化。

典型字段包括笔记创建时间、笔记 ID、标题、阅读量、商品点击次数/点击率、进店次数、支付金额、订单数、支付人数和退款金额。

笔记创建时间不是数据快照日期。没有快照日期时，不计算日新增阅读、日新增商品点击，也不判断自然流量的每日变化。

## 笔记元信息表

预期业务粒度：`笔记ID` 唯一。

典型字段包括 A/I 类型、笔记归属（达人/素人/KOS）、投放状态、产品、目标人群与卖点、内容模板、发现页/搜索页切口和人工标注。

同一笔记如果允许多个产品、模板或人群，先确认字段是多选、关联表还是多行展开。多行展开会造成事实表重复连接，未经处理不得直接聚合金额。

## 连接规则

- 使用规范化后的稳定 `笔记ID` 连接三表，不使用标题模糊匹配。
- 分别计算投流表到商品笔记表、投流表到元信息表的匹配数、缺失数和覆盖率。
- 一次性分析可以用业务键逻辑联查；要在 Base 中长期复用跨表字段时，再评估 link/lookup。创建关联字段属于写操作。
- 先把投流计划明细聚合到 `笔记ID × 日期`，再连接笔记级表，避免同一商品笔记指标被每个计划行重复计算。
- 投流支付与商品笔记支付保持不同字段名和来源标签；只有归因口径、时间窗和去重规则一致时才可比较，通常不相加。

## 质量检查

至少检查：

1. 字段类型：日期、数字、百分比、单选/多选和文本是否符合语义。
2. 关键键：笔记 ID 空值、异常格式、前后空格和重复。
3. 唯一粒度：投流表、商品笔记表和元信息表是否满足各自组合键。
4. 新鲜度：各表最大业务日期/快照日期、目标日记录数、今天数据是否尚未完结。
5. 数值合理性：负消费、负支付、负展现/点击、点击大于展现、零分母、退款大于支付等异常。
6. 口径一致性：金额单位、百分比是 `0.12` 还是 `12%`、时区、退款是否冲减 GMV、支付归因窗口。
7. 关联覆盖：投流笔记在表 2、表 3 中的命中率及缺失 ID 清单。
8. 分页完整性：任何 `has_more`、offset 或下一页标志都必须处理。

## 能力降级

| 缺口 | 仍可做 | 不可做 |
|---|---|---|
| 无计划字段 | 笔记日汇总 | 计划级诊断、计划去重证明 |
| 表 2 无快照日期 | 当前累计表现 | 日新增、自然流量日趋势 |
| 无消费或支付 | 流量/互动复盘 | ROI |
| 无展现或点击 | 成本/成交复盘 | CTR |
| 元信息缺字段 | 总体趋势 | 对应 A/I、归属、人群、模板等分组 |
| 关联覆盖不完整 | 已匹配子集并披露覆盖率 | 把子集结果写成全量结论 |
