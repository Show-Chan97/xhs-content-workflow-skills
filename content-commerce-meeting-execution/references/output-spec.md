# 输出规范

固定使用报告头和五个主体段落。没有内容的模块写“暂无”，不要删除模块。

## 报告头

```markdown
# {品牌名或待确认}｜内容电商会议执行作业纸

> 会议日期：{日期或待确认}
> 当前阶段：{冷启动/放量/成熟期/转型期/待确认}
> 分析来源：{妙记/逐字稿/纪要及范围}
> 证据说明：会议明确、上下文推断、建议、待确认已分开标注

## 🚨 P0 未认领提醒

本次共有 {n} 项 P0 尚未指定负责人：{事项列表或“0 项”}。

## 待确认清单

- {缺失字段、需谁补充、最晚何时补充}
```

## 第一段：待办事项拆解

```markdown
## 📋 待办事项拆解

| # | 待办事项 | 具体动作与交付物 | 依据/状态 | 优先级 | 负责人 | 开始时间 | 完成时间 | 验收证据 |
|---|---|---|---|---|---|---|---|---|
| 1 | {事项名} | {可二元验收的动作} | [会议明确] | P0 | {姓名或警示} | {日期或待补} | {日期或待补} | {链接/截图/数据表/确认记录} |
```

要求：

- P0 且未指定负责人的事项排在最前面；
- 不使用“优化内容”“提升转化”“加强种草”作为完整待办；
- 一个事项含多个独立交付物时拆成多行；
- 建议新增的验证动作标为 `[建议]`，不得写成会议决定。
- 预算、冻结变量、通过线和止损线默认写入相关事项，不单独占一行；它们没有负责人时也不计入 P0 未认领数量。
- 输入未给期限时，日期列写“待确认”或依赖节点；建议动作不得自行生成具体日历日期。

## 第二段：执行画像

只展开 P0 和 P1，每项使用同一结构：

```markdown
## 🔍 执行画像

### 事项 {编号}：{事项名}

- **负责人**：{姓名/角色/⚠️ 未指定·待补充}
- **优先级**：P0/P1
- **参考标准**：{合格标准；缺失时写确定标准的方法}
- **交付标准**：{完成/未完成的二元判断}
- **外部变量**：{触发条件 → 动作}
- **数据变量**：{触发条件 → 动作}
- **人员变量**：{触发条件 → 备用方案}
- **未完成的连锁影响**：{具体因果链；有数据才量化}
```

## 第三段：会议盲区

输出 3–5 项：

```markdown
## 👁️ 会议盲区

### 盲区 {编号}：{待验证问题}

- **证据状态**：[上下文推断]/[建议]/[待确认]
- **为什么该关注**：{与当前增长逻辑的关系}
- **不处理的后果**：{具体后果，不写空泛的“影响节奏”}
- **验证动作**：{建议角色或待确认} 在 {会议已给时间窗口/依赖节点/待确认} 内，用不超过 {会议已给投入上限/待确认}，检查 {已有范围/待确认的数据或样本}，把 {交付物} 放到 {位置或待确认}。
```

会议明显空转时，在本段末尾追加：

```markdown
### 会议效率提醒

{有时间戳时给出计算口径和占比；无时间戳时只做定性判断，并写“无法量化时间占比”。}
```

## 第四段：胜负手

只能有一个：

```markdown
## 🎯 {胜负手/暂定胜负手（待验证）}

当前阶段的胜负手是：{一句话}

**为什么是这件事？**

1. {依据一及证据标签}
2. {依据二及证据标签}
3. {可选依据三及证据标签}

**判断标准**：{单一可验证指标；没有现成阈值时先定义补数动作}

**赌赢后的连锁动作**：{A 成立后，哪些事项加速、停止或改变}

**赌输后的止损线**：{时间、预算/样本/机会成本、替代方向}

**转正还缺的证据**：{仅暂定时填写；否则写“无需”}
```

不要同时列“胜负手一、胜负手二”，也不要用“所有事项都做好”作为胜负手。

## 第五段：下一复盘节点

```markdown
## 📆 下一复盘节点

| 待办事项 | 负责人 | 当时优先级 | 当时定的标准 | 复盘类型 | 复盘触发条件 | 复盘节点 | 实际完成？ | 根因 | 下一步 |
|---|---|---|---|---|---|---|---|---|---|
| {事项 1} | {负责人} | P0/P1/P2 | {原验收标准} | {进度/结果/决策/风险复盘} | {可观察条件} | {日期/里程碑/数据条件/风险事件/待确认} | ✅/❌/待复盘 | {变量/执行/判断/待确认} | {继续/调整/放弃} |

每位负责人复盘时回答：

1. 我负责的事做完了吗？没做完卡在哪里？
2. 执行过程中发现了什么之前不知道的信息？
3. 基于新信息，下一轮继续、调整还是放弃？
```

复盘表必须覆盖第一段中的全部待办，不能只覆盖 P0/P1。复盘节点按“会议明确时间 → 已确认交付日期或里程碑 → 已确认数据条件或风险事件 → 待确认”的顺序确定，不统一增加 14 天。

复盘类型使用：

- `进度复盘`：检查任务是否完成以及卡点；
- `结果复盘`：在交付完成且数据具备判断条件后验证结果；
- `决策复盘`：达到通过线、止损线或关键决策条件时决定继续、调整或停止；
- `风险复盘`：外部、数据或人员风险触发时立即重新判断。

## 结构化交付附件：会议复盘 Base 交付包

用户要求表格化交付或新建飞书多维表时，必须同时准备【行动与动态复盘表预览】和【Base 内报告文档预览】，并完整遵守 [base-action-output.md](base-action-output.md)。行动表固定使用以下十四列：

| 核心问题 | 板块 | 解决方案 | 优先级 | 负责人 | 协同人 | 截止日期 | 状态 | 复盘类型 | 复盘触发条件 | 复盘节点 | 验收证据 | 复盘结论 | 下一步 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| {会议证据支持的问题} | {本次会议板块} | {动作；交付物；验收标准} | P0-紧急/P1-重要/P2-常规 | {姓名/角色/待确认} | {姓名/角色/空} | {日期/空} | {状态} | {进度/结果/决策/风险复盘} | {可观察条件} | {日期/里程碑/数据条件/风险事件/待确认} | {链接/截图/数据表/确认记录} | 待复盘 | {复盘后的动作或待确定} |

要求：

- 预览记录与第一段待办一一对应，记录数必须相同；
- 截止日期未确认时留空；复盘节点可以保留原相对期限、里程碑、数据条件、风险事件或“待确认”；
- 新拆事项没有状态证据时统一为“待启动”；
- 新拆事项的复盘结论统一为“待复盘”；
- 表格预览不代表已创建飞书 Base，实际创建前仍需“确认执行”；
- 用户未要求表格化交付时，不强制追加本附件。

报告文档预览使用本文件规定的报告头和五个主体段落，不另写简版。实际交付时，在同一个 Base 内新建报告文档并写入该完整内容。只有行动表与文档都通过飞书 CLI 回读，且待办数量、优先级、负责人和验收标准一致，才算 Base 交付包完成。

Base 名称固定为 `YYYY-MM-DD-品牌-会议主题会议`。会议主题优先从会议标题和核心议题自动识别，并在执行确认单中人工确认；只有无法可靠判断时才询问用户输入。会议主题本身已以“会议”结尾时不重复追加。会议日期、品牌或会议主题尚未确认时，只输出待确认名称预览，不实际创建 Base。

## 交付前检查

- [ ] 报告头、待确认清单和五段主体齐全；
- [ ] P0 未认领项在开头突出显示；
- [ ] P0 未认领数量只统计待办行，不把约束、阈值或待确认字段另算一项；
- [ ] 待办均有验收证据，且能二元判断；
- [ ] P0/P1 均有执行画像和三类变量；
- [ ] 盲区为 3–5 项，并明确是待验证假设；
- [ ] 胜负手恰好一个，含判断标准、赢后动作和止损线；
- [ ] 所有负责人、日期、阈值和数据有来源或标为待确认；
- [ ] 建议没有自行补具体日历日期、预算、样本量、基线或目标值；
- [ ] 动态复盘表覆盖全部待办，每项都有复盘类型、触发条件和复盘节点；
- [ ] 未经会议或用户确认时，没有自行生成 7 天、14 天、30 天或其他固定复盘周期；
- [ ] 无时间戳时没有虚构会议时间占比。
- [ ] 用户要求多维表时，已输出十四字段预览和完整报告文档预览，且记录与报告待办一一对应；
- [ ] 实际创建 Base 前已展示 Base、数据表、报告文档、schema、选项、行数和目标位置，并获得“确认执行”；
- [ ] 完成时已分别回读 Base 资源目录、行动记录和报告文档，且内容一致。
