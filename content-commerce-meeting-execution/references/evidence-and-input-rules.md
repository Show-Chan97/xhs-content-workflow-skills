# 输入与证据规则

## 1. 最小输入

必须有：

- 一份可读取的会议记录：逐字稿、妙记正文、纪要或录音转写。

建议有：

- 品牌名与品类；
- 当前阶段：冷启动、放量、成熟期或转型期；
- 会议日期与本轮复盘周期；
- 已知负责人和团队角色；
- 当前数据、目标、预算、库存与产能信息。

只有会议链接但无法读取正文时，不生成分析。先说明读取失败，再请求用户粘贴正文或提供可访问版本。

品牌、品类或阶段缺失时可以输出候选版，但必须在报告头列入待确认清单，相关胜负手标为暂定。

如果用户要求实际创建会议复盘 Base，会议日期、正式品牌名和会议主题是命名必填项。任一缺失时仍可完成报告和行动表预览，但必须停在创建确认前；不得用执行日期代替会议日期，也不得自行编造品牌或会议主题。

## 2. 四类证据标签

| 标签 | 含义 | 允许的写法 |
|---|---|---|
| `[会议明确]` | 会议中明确出现的决定、姓名、日期、数据或承诺 | 可直接进入待办和执行画像 |
| `[上下文推断]` | 可由相邻语句或依赖关系合理推出，但会议未直接说出 | 写明推断依据，并允许用户纠正 |
| `[建议]` | 为补全执行闭环新增的动作、标准或验证方法 | 不得表述为会议决定 |
| `[待确认]` | 缺少负责人、日期、阈值、数据口径或事实依据 | 明确缺什么、由谁补、何时补 |

同一条内容可以同时含事实和建议。分句标注，不要用一个标签覆盖整段。

## 3. 禁止补写的内容

- 未在材料中出现的具体负责人姓名；
- 未给出的开始日期、完成日期或会议日期；
- 未给出的当前值、目标值、预算、销量、ROI、点击率或退货率；
- 没有来源的行业均值、竞品动作、平台规则变化；
- 由沉默、语气或简短发言推断的个人态度、能力或组织关系；
- 把文档中的示例阈值当成所有品牌通用标准。

需要数字但输入没有数字时，改写为：

```text
[待确认] 当前基线：未提供
[建议] 标准确定方法：先取得同口径历史数据（观察窗待确认），再由负责人确认目标值和止损值
```

## 4. 日期与相对时间

- 会议明确给出具体日期时原样使用。
- 会议明确说“本周”“两周内”等相对期限时保留原相对时间；只有用户要求换算时，才结合会议日期计算具体日期并标注 `[上下文推断]`。
- Skill 固定包含“两周复盘表”，不等于会议已经约定两周后的具体日历日期。未约定复盘日期时写“两周复盘节点：具体日期待确认”，不要自动加 14 天生成日期。
- 没有会议期限时不要给 `[建议]` 动作补具体日历日期。在日期列写 `⚠️ 待补充`，或用“数据口径确认后”“首批发布前”等依赖节点。

## 5. 负责人和资源决策

- 会议明确指定姓名时写姓名。
- 会议只指定职能时写职能，例如“内容负责人”。
- 完全未指定时写 `⚠️ 未指定·待补充`。
- 可以指出 A、B 两项存在时间或能力冲突，也可以说明需要不同角色；不要替老板决定由哪位具体成员承担。

预算上限、冻结变量、通过线和止损阈值通常是行动项的约束，不是新的行动项。不要因为约束没有单独负责人，就把原本负责人完整的会议误报为“P0 未认领”。

## 6. 建议动作的数值边界

当会议没有给出对应信息时，建议动作不得自行补：

- 具体日历日期；
- 预算或工时上限；
- 样本量、观察天数；
- 指标基线、目标值、通过线或止损值。

改用依赖节点和占位信息：

```text
建议角色：数据负责人（具体姓名待确认）
完成节点：正式测试启动前
投入上限：待确认
样本与观察窗：待确认
```

## 7. 外部资料

默认不主动把外部资料混入会议分析。用户明确要求补充行业或竞品资料时：

1. 单列来源和检索时间；
2. 把外部资料标为 `[外部资料]`；
3. 说明它与会议结论是支持、冲突还是尚无关系；
4. 不用外部行业均值替代品牌自己的基线与目标。

## 8. 跑题与会议效率

- 有带时间戳逐字稿时，可以按时间区间估算某话题占比，并说明计算口径。
- 没有时间戳时只能定性判断讨论是否偏离 P0/P1，明确写“无法量化时间占比”。
- 不因为发言少就推断成员消极，也不因为发言多就推断其承担责任。
